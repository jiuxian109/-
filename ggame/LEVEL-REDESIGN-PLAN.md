## 1. 三条新增机制（改 `game.js`）

三条机制都在**既有视觉语言**内有对应物，不引入新色相、不引入 emoji/渐变。
**三条均已实现并落地**（`game.js` 1881 → 2019 行，`node --check` 通过）；下文每条末尾的
`✅ 已实现 · 当前行号` 是**改动后的实际位置**（本节正文里的旧行号保留为「改前」参照）。

### M1 · 护心块 `kind:'protect'` —— 「连锁撞不倒，只认奶龙直击」

- **规则**：普通木块被撞倒时会连锁带倒邻居；护心块**免疫连锁**，只有奶龙本体直接命中才倒。
- **视觉**：块面用 `C.wood`（#9a7048）打底，中央画一圈 `C.ink3`（#6b6353）的**木鱼纹**
  （同心圆 + 一道穿线，4 条线宽 2px 的圆环弧），比普通块的纯色面多一道「纹」。
  倒下的那一刻纹路随块旋转 —— 读起来就是「这块是硬的」。
- **音效**：被连锁撞击时**不发声**（这是教学信号：没反应 = 打不动）；
  被奶龙直击倒下时用 `wood()` 原语（`wood(150, 0.22, 0.5, 4)`）—— 比普通块的 `sClear()` 更低更闷的木鱼声。
- **`game.js` 改动点**：
  - `addBlock(x, y, w, h)` **改前 game.js:493-502** → `addBlock(x, y, w, h, kind)`，把 `kind` 存进
    `b = { body, w, h, x, y, x0, y0, kind }`，并写 `body._block = b`（沿用现有约定）。
  - `applyImpactBoost(A, B)` **改前 game.js:583-604** → 加一行
    `if (!byBird && blk._block && blk._block.kind === 'protect') return;`
    （护心块拿不到撞击冲量，因此永远不会被连锁推翻）。
  - `buildLevel` **改前 game.js:519-539** → `addBlock(blk.x, blk.y, blk.w, blk.h, blk.kind)`。
  - 木块绘制函数 → 按 `kind` 叠加木鱼纹。
  - `sClear(kind)` → 增加护心分支（见上）。
  - ✅ **已实现**：`addBlock` **game.js:514**；`applyImpactBoost` **game.js:609**，落点
    **game.js:617-618**；`buildLevel` **game.js:545**；`drawBlock` 护心纹 **game.js:1179**；
    `sClear` 护心分支 **game.js:441**。击倒阈值另按 kind 分档于 **game.js:729-732**。

### M2 · 落印块 `kind:'seal'` —— 「朱砂印，压平才算」

- **规则**：普通块只要「位移 > 45px」就计倒；落印块**必须被真正压平**才算 ——
  判据收紧为 `fell / tilted / moved` 的阈值从 `22 / 0.7 / 45` 改成 `30 / 0.5 / 60`，
  且**额外要求**：若只有 `moved` 成立（既没掉下去、也没倾翻），则**把 `moved` 打回 false** ——
  即 **`moved` 单独不能算落印**，必须出现明显的姿态改变（掉 30px 或倾 > 0.5rad）。
- **视觉**：块面画一枚**朱砂印**（`C.seal` #b23a2e 的圆角方印 + 白色阴文笔画），
  位置随块旋转；「压平」那一刻印面被压扁贴在岛面上。
- **音效**：压平瞬间 **`seal()`**（**game.js:297**，项目已有的签名动作音：木 + 延迟 15ms 的磬，
  磬过 lowpass 从 500→4000Hz 在 0.12s 内 bloom）—— 这就是「落印」二字的音画对齐。
  普通块继续走 `sClear()`。
- **`game.js` 改动点**：
  - 击倒判定 **改前 game.js:686-688** → 现为
    `const fell = p.y > b.y0 + 22; const tilted = Math.abs(body.angle) > 0.7; const moved = Math.abs(p.x - b.x0) > 45;`
    改为按 `b.kind` 取三套阈值（普通：`22/0.7/45`；护心与落印：`30/0.5/60`），落印再叠一条
    「`moved` 单独不算」的收口。
  - `sClear()` 调用点 → 落印块改调 `seal(0.5)`。
  - 木块绘制 → 按 `kind` 叠加朱砂印。
  - ✅ **已实现**：击倒分档 **game.js:716-737**（落印收口在 **game.js:724-728**）；
    `sClear` 落印分支 **game.js:437**；`drawBlock` 落印纹 **game.js:1190**。

### M3 · 长引 `pull ≥ 100px` —— 「把手拉满」

- **规则**：把「这一发的拉弓距离 ≥ 100px」记为**长引**。不新增实体、不新增 HUD 元素，
  只统计既有输入（`maxPull`）。**字段与实现保留，但四关的 `goals` 一条都没用**（理由见 §3.1）。
- **视觉**：奶龙拉弓时，皮筋在**拉满区**（`pull/MAX_DRAG ≥ 100/130 ≈ 0.77`）由 `C.ink3` 转为
  **`C.seal` 朱砂**；拉满后再松手，出手瞬间皮筋留下一道更长的**朱砂余痕**（乘 `maxPull/MAX_DRAG` 决定长度）。
  不新增色相 —— 朱砂本就是「动作色」。
- **音效**：`pullUpdate(t)`（常驻声）在跨越 0.77 阈值时触发一次**死区 tick**：
  复用已有的 `minTickDone` 闩锁机制加一枚 `longCrossed` 闩锁，响 `wood(520, 0.05, 0.35)`（高音木点）。
  玩家听到「嗒」就知道拉满了 —— **零新音色，零新原语**。
- **`game.js` 改动点**：
  - `maxPull` 已有 → 在 `fireBird()` **改前 game.js:843** 里 `if (maxPull >= LONG_PULL) longPulls++;`；
  - `buildLevel` / `clearLevel` → `longPulls = 0; firstShotKills = 0;`；
  - 另记 `shotIndex` 与 `shotKills`，在 `onSettle()` 里把第 1 发的击倒数搬到 `firstShotKills`，
    供星级判据 `minKill1` 使用。
  - ✅ **已实现**：`LONG_PULL = 100` 与三个统计量声明 **game.js:147-159**；
    `longPulls++` **game.js:906-908**；`firstShotKills` 结算 **game.js:801-802**；
    皮筋转朱砂 **game.js:1330-1334**；越阈值木点 **game.js:370-372**。

## 2. 四关重画（坐标表 + 三星判据 + 难度理由）

**通用约定**（与 `game.js` 一致）：世界 960×540，原点左上，y 向下；`islands` 用 `cx` 水平中心、
`top` 岛面 y；`blocks` 的 `x, y` 是**中心**，默认尺寸 44×44。
**所有块都栅格化**：贴岛面时 `y = top − h/2`，向上叠一律 `y −= h`；并排一律 `x ± 44`（不再有 1–5px 缝）。
发射台恒为 `{cx:150, top:470, w:320, h:120}`（**不可动** —— 弹弓常量 SLING_BASE(185,470) 写死）。

但它不再能一发给空：主塔 3 块竖排 + 高台 3 块（2 竖 + 1 骑缝悬挑），

### 3.1 判据原子（`type` 白名单）

| type | 字段 | 语义 | 数据来源（`game.js`） |
|---|---|---|---|
| `clear` | — | 全部木块放倒 | `blocks.length === 0` |
| `maxShots` | `value` | 通关用发数 ≤ value | `levelShots − shotsLeft` |
| `minKill1` | `value` | **首发**一杆放倒 ≥ value 块 | `firstShotKills`（新，`fireBird` 记 `shotIndex`，`onSettle` 搬运） |
| `minLong` | `value` | 至少 value 发为长引（pull ≥ `LONG_PULL=100`） | `longPulls`（新，`fireBird` 记录） |
| `maxKill1` | `value` | 首发一杆放倒 ≤ value 块（预留：「不许大开大合」类挑战） | `firstShotKills` |
| `maxLong` | `value` | 长引发数 ≤ value（预留） | `longPulls` |
| `minScore` | `value` | 总分 ≥ value（每块 100 分） | `score` |
| `all` | `of: [...]` | 全部子判据成立 | 递归 |
| `any` | `of: [...]` | 任一子判据成立 | 递归 |
| `not` | `of: [x]` | 子判据不成立（本期未用） | 递归 |

> **`minLong` / `maxLong` 的诚实说明**：两个字段**已经实现进 `game.js`（`evalGoal` 的 `case 'minLong'` /
> `case 'maxLong'`），但本文四关的 `goals` 一条都没用它们**。原因见 §2.2 / §2.4 的实测：
> `longPulls` 在这四关里是「拉满引」的自然产物（L2 通关路线 82% 含长引、L4 50%），
> 拿它当判据会让星级**过松**（区分度不足），所以改用 `minKill1`（首发一杆的块数）作主判据。
> 字段留着是为了以后做「必须拉满」的限力关，**当前是死代码**，这是已知且刻意的。

**不变式（`verify-geom.mjs` 里加一条断言校验）**：对每关 i，
`sat(goals[0]) ⊇ sat(goals[1]) ⊇ sat(goals[2])` —— 即**满足三星必然满足二星、满足二星必然满足一星**。
否则会出现「拿了 3 星却不是 2 星」的荒谬结算。本文四关判据均满足（构造时即按此约束写）。

- `kind` 缺失 → `'plain'`，与旧数据完全等价。
- `blocks` 里的 `w/h` 仍可省略（默认 44×44）。

### 5.5 本轮抓出的两个保真度缺陷（**这是本次交付最重要的诚实记录**）

在「把离线工具的判定逻辑与 `game.js` 对齐」这一步上，我**先后犯了两个错**，都是靠
「用真实引擎 + 逐字比对源码」抓出来的。**它们让前两轮的所有 L2/L4 难度数字作废。**

**缺陷 1 · 离线核心把所有块都按 `plain` 阈值判定（导致 L2/L4 数字系统性偏乐观）**

- `game.js:741-747` 对 `seal` / `protect` 用的是**收紧后**的阈值 `fell 30 / tilt 0.5 / moved 60`，
  且 `seal` 额外有一条「只有 `moved` 成立时打回 false」（平推不算落印）。
- `editor/_sim-core.mjs` 原来对**所有块**都用 `plain` 的 `22 / 0.7 / 45` → 护心块与落印块
  在离线里**比真机更容易倒**。L2 / L4 是唯二含这两种块的关卡，所以只有它俩的数字受影响。
- **已修**：`editor/_sim-core.mjs:151-177` 现在按 `_kind` 分三档，逐字对齐 `game.js`。
- **影响量级**：L4 的通关路线从 169 条缩到 **65 条**，最少发数从 **2 变成 3**；
  L2 从 312 条变 325 条、首发平均从 4.47 变 4.43（几乎不变）。
  **也就是说：修复前 L4 的「2 发通关」是个假结论。**

**缺陷 2 · `protect` 块在真机里永远倒不了（会让 L2/L3/L4 直接无法通关）**

- `game.js` 里「护心块免疫连锁」的实现是一条 `continue`：
  `if (kind === 'protect' && !b.hit) continue;` —— 意思是**奶龙没直击过它，就完全不参与击倒判定**。
- 但我漏了两件事：**`hit` 字段从未初始化**，也**从未被置位**。
  于是 `!b.hit` **恒为 true** → **护心块永远 `continue`，永远不倒**。
- 后果：L2 / L3 / L4 的 ★ 判据要求「放倒全部 N 块」，而护心块在真机上无法放倒
  → **三关全部不可能通关**。这是**致命 bug**，离线搜索**抓不到**（因为离线核心里 `_hit` 是正确实现的），
  只能靠读源码发现。
- **已修**（两处）：
  - `game.js:522` — `const b = { body, w, h, x, y, x0: x, y0: y, kind: kind || 'plain', hit: false };`
  - `game.js:653-658` — 在 `collisionStart` 里、**`applyImpactBoost` 之前**（因为它对护心块会提前
    `return`）加直击记账：
    ```js
    const birdIsA = (A.label === 'bird'), birdIsB = (B.label === 'bird');
    if (birdIsA || birdIsB) {
      const other = birdIsA ? B : A;
      if (other.label === 'block' && other._block) other._block.hit = true;
    }
    ```
- **顺带发现的一处死代码**：`game.js:628` 的 `if (!byBird && blk._block && blk._block.kind === 'protect') return;`
  **永远不会生效** —— `applyImpactBoost` 在更早的 `game.js:621` 就 `return` 掉了「两侧都不是奶龙」的情况，
  所以进到那一行时 `byBird` **恒为 true**。它不造成错误（护心免疫真正靠的是那条 `continue`），
  但**读起来像防线、实际不是**。保留它无害，但**不要**以为护心里程在那里。

**教训（写给下一轮的人）**：离线物理仿真能验证「几何与预算」，**不能验证「我在真机里把机制接对了没有」**。
`hit` 这个漏接，用真引擎跑一万次搜索也跑不出来 —— 因为离线核心里我是**先写了正确版本**，
所以两边「逻辑一致、但真机那侧没接线」。**凡是新增机制，必须同时写一条「真机路径」的断言**，
这就是 §5.2 那两条断言（A1–A4，现已补齐）的由来（护心块无法连锁推翻、落印块轻推不算 ——
这两条现在是 `editor/check-mechanics.mjs` 里的可执行断言，见 §5.2 的断言表）。
