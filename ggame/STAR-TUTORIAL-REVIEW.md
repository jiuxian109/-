## 2. 星级阶梯设计：先说一个硬约束，它决定了整个方案

### 2.1 「只看剩余发数」下的三档判据长什么样 —— 以及 `two` 为什么只能是 `three + 1`

**【码】** 游戏只认一个结果：木块全倒（`starsFor()` 只在通关时被调用，`goalCtx()` 里 `cleared: true` 恒真，`game.js:1741-1781`）。所以三档判据必然是「通关 + 一条关于剩余发数的阈值」：

```
1★ = 通关
2★ = 通关 且 剩 ≥ stars.two 只
3★ = 通关 且 剩 ≥ stars.three 只        （three > two）
```

换算成「用掉几发」：**3★ = 用 ≤ B − `three` 发**，**2★ = 用 ≤ B − `two` 发**。

设本关奶龙额度 `B`、离线实测最少通关发数 `M`。两条硬约束：

1. **`three` 必须满足 `B − three ≥ M`**，否则三星是**恒假条款**（上一轮踩过的坑：L4 曾写「2 发 AND 首发 ≥8 块」，几何上 0/65 可达）。取到等号就是「一发都不能浪费」。
2. **`two` 只有两个有含义的取值**：`three + 1`，或者等于 `three`（那样二星与三星重合、二星消失）。一旦 `two > three + 1`，二星的含义就变成「你浪费了两发以上也算」，**档位立刻退化成保底**——现在的 `stars.two = 1` 在 B=6 时就正是这种情况（用掉 5 发也算二星）。

**结论：真正可调的旋钮只有三个 —— `B`（额度）、`three`（三星保留几发）、`M`（摆放决定的最少发数）。`two` 没有自由度，永远是 `three + 1`。**

**【推】给关卡设计师的硬话**：不要再花时间试「阈值取 2 还是 3」，也不要动 `two` 的绝对值 —— 先量出 `M`，确认 `B − three ≥ M`，然后把 `two` 一律写成 `three + 1`。**当前 `levels.js` 四关的 `stars` 都是 `{ three: 2, two: 1 }`；`three: 2` 在四关都成立（见 2.4），要改的只有 `two`。**

### 2.2 当前 `game.js` **完全没有读**新的 `stars` / `teach` 字段（必须实现，否则本轮所有星级设计都是空转）

**【码】** 关卡设计师已经把 `levels.js` 改成了新结构（`stars: { three, two }`，并删掉了 `goals`），但 `game.js` 还停在旧协议上：

- `starsFor()`（`game.js:1767-1781`）只读 `L.goals`。`goals` 已被删除 → **恒走回退分支** `if (shotsLeft >= 2) return 3; if (shotsLeft === 1) return 2; return 1;`（`game.js:1770-1773`）。
- **巧合**：四关 `stars.three` 都是 2，所以「剩 ≥2 发 = 3★」这条**恰好正确**；但「剩 1 发 = 2★」在 B=6 的额度下几乎恒真（除非把 6 发全打光）→ **二星档事实上消失**（见 2.4 的二星表）。
- `nextGoalHint()`（`game.js:1783`）同样只读 `L.goals` → 结算面板的「下一星：…」提示**整条失效**。
- `grep teach|教学|提示卡` 在 `game.js` 只命中一处无关的 `winVideo.pause()`（`game.js:1844`）→ **`L.teach` 的四张教学卡是死数据，一张都不会弹**。

**主理人需要安排的最小改动（按优先级）**：

1. `starsFor()` 改读 `L.stars`：`if (shotsLeft >= L.stars.three) return 3; if (shotsLeft >= L.stars.two) return 2; return 1;`
2. `nextGoalHint()` 改成从 `L.stars` 生成文案（「再省 1 发 = 三星」），或直接删掉这个提示。
3. 实现 `teach` 流程（§3.3 给了完整的暂停/恢复条件）。

### 2.3 怎么让玩家一眼看懂二星和三星的差别

一个词：**把阈值换算成「剩几发」，并且让这个数字常驻、可倒数。**

**【码】** 现在 HUD 已经有 `剩余 × N` 芯片（`game.js:1608/1626/1628`）。这是本项目最大的资产 —— 它已经就是星级刻度本身。要补的只有「刻度线画在哪」。

**HUD 提案（三处，改动都很小）**

1. **芯片直接写门槛，而不是只写数量**：`剩余 × 2 ／ 3★` 改成两段式排版 —— 左侧数字大号，右侧小号朱砂字写 `3★ 需 ≥2`。这样每关门槛不同也不会有认知断层，玩家不需要跨关记忆。
2. **首发之后立刻给「已失去的星」提示**：第 1 发打完的提示卡（`chip` 机制已有，3.6 秒淡出）最后一行追加：
   - 还剩 2 只：`再省 1 发就是三星`
   - 还剩 0 只：`这一把三星没了，三星要 2 发内`
   **只有「失去」需要提示，「还在手上」不需要。** 这条符合损失厌恶，也避免每次发射都刷屏。
3. **不要用星星图标做实时状态显示**。空心星 → 灰星（已失去）→ 亮星（已到手）这套三段式，会让「还能拿三颗」和「已经丢了一颗」在余光里长得一样。**用奶笼数量做刻度，用星星只做结算。** 图纸 `course/design-star-ladder.svg` 给的就是这个刻度画法。

**结算面板提案（`game.js:1820` 那行文案）**

现在写的是「用 X 发 · 首发 N 块」。改成带刻度的：

```
★★☆   你用了 3 发 · 三星要 2 发内（差 1 发）
```

三个要点：① **把差多少写成「差 1 发」而不是「剩 1 只」** —— 差值是行动指令，剩余量是状态；② 把「首发 N 块」从结算面板删掉（那套判据已经取消，留着会让玩家以为还有别的得分方式）；③ 三星拿到时不写差值，写「比最少发数就多花了 0 发」之类的确认语，让玩家知道自己踩到了极限。

**【推】风险**：HUD 芯片是全局复用的（手机竖屏还有第三个位置 `game.js:1626`）。加字会撑宽芯片，触屏布局要一起量。这条建议在实装前先量一次移动端芯片宽度。

### 2.4 三星率 30–50%：现状已经落在带内（**这一节全部换成实算数字**）

**【算】** 关卡设计师重写后的 `levels.js` 头部注释里已经带了实测分布（`editor/run-sample.mjs --n 8000`，每关 8000 条随机路线、离线仿真、非真人）。这是**唯一一份玩家层面的数据**，比任何路线构成比都更贴体验，所以本文以它为准：

> **定义 A（玩家基准率，本文主用）**：随机打一条路线，最终剩 ≥ `stars.three` 发的概率。
> **定义 B（路线构成比，§ 里的 `share`）**：所有通关路线里「用发数 ≤ B − three」的条数占比。它衡量**几何上留了多少余量**，不是玩家能不能拿到。

| 关 | 额度 B | `stars.three` | 三星 = 用 ≤ | 用发分布（8000 抽样） | **三星基准率** | 判定 |
|---|---|---|---|---|---|---|
| 1 云间初试（教学） | 6 | 2 | 4 发 | 2/3/4/5/6 = 2/17/38/49/51 | **87.9%** | 刻意超标：教学关不该卡星 |
| 2 叠叠高 | 6 | 2 | 4 发 | 65/131/196/231/263 | **57.1%** | 略高于带上限 |
| 3 一柱擎天 | 6 | 2 | 4 发 | 9/22/33/40/52 | **46.2%** | 落在带内 ✅ |
| 4 巅峰论道（收束） | 7 | 2 | 5 发 | 3/7/10/14/29/25 | **39.0%** | 落在带内 ✅ |

**三星率的阶梯形状是对的**：88% → 57% → 46% → 39%，一条单调下降的曲线，教学关明显最松、收束关最紧。这比「四关都卡在 40%」更像一套设计。**唯一建议**：第 2 关的 57.1% 里有一大块是「恰好用满 5 发」的路线（263/886 = 29.7%）——它其实离三星只差一发，是「差一点」最密集的一关，说明**第 2 关是最好的「再省一发」教学点**，不必压它。

**二星档现在几乎不存在，这是真正要改的一处（【算+推】）**：`stars.two = 1` 的含义是「剩 1 发 = 二星」，也就是**用掉 B−1 发也算二星**。按上表分布换算：

| 关 | 二星 = 用 ≤ | 拿到 ≥2★ 的比例 | 只拿 1★ 的比例 | 结论 |
|---|---|---|---|---|
| 1 | 5 发 | 99.4% | 0.6%（只有把 6 发打光才掉） | 二星 = 保底 |
| 2 | 5 发 | 92.4% | 7.6% | 二星 ≈ 保底 |
| 3 | 5 发 | 86.5% | 13.5% | 二星 ≈ 保底 |
| 4 | 6 发 | 67.0% | 33.0% | 只有这一关二星有含义 |

> **建议**：四关的 `stars.two` 由 `1` 改为 **`3`**（即「用 ≤ `three + 1` 发」）。这样二星变成「你通关了，但比三星多用了一发」，四关都成立，且**不需要动 `birds`、不需要改摆放**。
> **为什么 `two` 只能是 `three + 1`**：见 2.1 的守恒律 —— 三档阈值只能取 M、M+1、B 这三个数。`two > three + 1` 就等于把二星让给「浪费两发以上」的人，档位立刻退化成保底；`two < three + 1` 会让二星与三星重合。

**两条给关卡设计师的提醒：**

1. **`B` 调大 = 三星变松，不是变紧**。三星要的是「剩 ≥ `three` 发」，而 `three` 是固定小整数（现在四关都是 2），所以 `B` 越大、允许你用的发数越多。第 1 关的 87.9% 就是这么来的：B=6、`three=2` → 用 ≤4 发就三星，而它的最少发数只要 2 发。**反过来，想让三星变难只有两条路：把 `three` 调大，或让摆放把 M 顶上去。**
2. **`three` 一旦大于 `B − M`，三星就是恒假条款**（上一轮踩过的坑：L4 曾写「2 发 AND 首发 ≥8 块」，几何上 0/65 可达）。`three` 只能取 `1 … B − M`，**取到 `B − M` 就是「一发都不能浪费」**。
3. **别为了让三星率落在 30–50% 而去砍 `birds`**。设计师的抽样已经把四关压到 88/57/46/39 —— 除了教学关刻意宽松，其余三关的形状是对的。要动的只有 `stars.two`。

### 2.5 一星的真实地位（必须对主理人说清楚）

**【码+推】** 在「只看剩余发数」下，1★ 只可能是「通关即得」。它**不可能**是有含金量的档位：任何比「通关」更严的 1★ 判据都会变成「二星」，而比通关更松的判据不存在。

所以三档的真实结构是：

```
1★ = 完成关卡的里程碑（不是成绩）
2★ = 「你完成了，但浪费了一发」
3★ = 「你摸到了这关的极限」
```

**【推】产品建议**：不要在结算面板把 1★ 画成「一颗星」（价值暗示太强）。用「通关印记」之类的称呼，或者在视觉上把 1★ 处理成印章、2★/3★ 处理成墨点，让玩家不会把「一星」当成差评。**另一个选择是接受它，但让 1★ 的文案是「过」而不是「一星」**——这条需要主理人拍板。

### 2.6 「再省一发就能多一颗星」的可预见性 —— 三条具体做法

1. **门槛可见**（§2.3 第 1 条）：HUD 常驻 `3★ 需 ≥N`。
2. **差值可见**（§2.3 第 2 条）：发射后只在「刚丢掉一颗星」时提示差多少。
3. **代价可重试**：`重来` 必须永远在一步之内（**【码】** 现在 HUD 有重来芯片 `game.js:1595-1619` 区域）。三星率 30–50% 意味着**大多数人要打第二遍**，所以「重来→再试」的时间成本必须接近零。建议重来后**保留同一关的 HUD 提示文案**，不要回到教学卡（见 §3 的恢复条件）。

## 3. 第 1 关教学关设计（三段教学：基本发射 → 护心块 → 落印块）

### 3.1 设计三条铁规矩（先立规矩，再写文案）

1. **一张卡只教一件事**：卡上只出现「一个动作 + 一条规则」，任何第二件事拆到下一张卡。
2. **卡是白送的，答案不是白送的**：暂停、给时间、给规则，但**不给角度**。
3. **一段教学 = 一次允许的错**：让玩家用一次「错」来认识规则，比让他读三行字快得多。

### 3.2 三段教学的落点（必须说清楚：三段不在同一关）

用户原话是「第 1 关改为教学关，依次教基本发射、护心块规则、落印块规则」，而第 1 关现有的 6 块里**没有护心块、也没有落印块**。两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 第 1 关教「基本发射 + 连锁 + 悬挑」两段；**护心卡搬到第 2 关首屏**（那关本来就是护心块首秀）；**落印卡搬到第 3 关**（第 2 关右岛有落印块，但那关的注意力已经给了护心块） | 三段教学分布在三关，跨关不连续 |
| B | 在第 1 关塞进护心块与落印块各一枚，三段同关 | 第 1 关「云间初试」的气质会变成规则宣讲；6 块的摆放要重排，工作量远超「木块摆放为主的微调」 |

**方案 A 的三个理由**：① 三段同关必然连出三张卡，节奏碎成一节课，违背「不变成读说明书」；② 第 1 关额度里要分出「浪费一发去试错」的预算，教学完就没得玩了；③ 护心块/落印块的认知需要「在真实压力下想起来」，**跨关记忆比同关背诵更像学会**。

**A 方案的配套**：第 2 关的护心块本来就在首屏最显眼处（可命中方向 10/37，见 §4.3），是天然教具；第 3 关结构最丰富，多一张卡代价最小。

### 3.3 三段教学的顺序、时机与恢复条件

| 段 | 关卡 | 教什么 | 出现时机（精确） | 玩家怎么做才算过 |
|---|---|---|---|---|
| ① 基本发射 | 第 1 关 | 拖拽 → 瞄准 → 松手 | 玩家**第一次把奶龙拉过 `MIN_PULL`（死区线）**的那一刻 | 第一发打完并结算 |
| ② 拆底 | 第 1 关 | 拆底块 = 拆整列；顺带说清三星只数与空放不扣发 | 第 1 发结算后的回合就绪时刻，**紧接在结果之后**（玩家刚看见塔塌了） | 看一眼结果，关掉卡 |
| ③ 护心 | 第 2 关 | 护心块免疫连锁，只能直击 | 玩家**第一次把护心块作为瞄准对象** —— 判定：松手瞬间的瞄准射线（`ANCHOR → 力度终点`）与任一护心块外接矩形相交 | 该发打完，看到护心块纹丝不动 |
| ④ 落印 | 第 3 关 | 落印块要压平/掀翻，平推不算 | 同上，瞄准射线与任一落印块相交时 | 该发打完，看到落印块没生效 |

> ⚠️ **实现注意（【码】）**：`state` 是 `ready | dragging | flying | settled | won | lost`（`game.js:154`）。**暂停必须发生在 `ready`**（奶龙已生成或即将生成、还没拖拽），也就是回合就绪回调里（`game.js:873-876` 一带）—— 那里 `state` 刚被置成 `settled`，`update()` 不会累积拖拽输入，是最干净的挂点。**不要在 `dragging` 中途暂停**：松手事件会丢，奶龙会卡在手里。
> ⚠️ **另一条**：拉过死区线那一刻（`game.js:370` 的 `crossed`）**之前不要弹卡** —— 那之前玩家只是在摸屏幕。死区线本身画在力度条上（`game.js:1538-1539`），拉过它时条子会变色，**那一刻注意力最高，卡弹在这里最不像干扰**。

**暂停与恢复的完整规则（四条，缺一不可）**

1. **暂停**：卡出现 → 物理暂停、输入屏蔽（拖拽不再响应），**但画面继续呼吸**（云的飘动、墨晕动画不停）。理由：完全冻帧会让画面看起来「卡了」；保留环境动效，玩家读卡时会一直有「游戏还活着」的知觉。
2. **恢复**：**只由玩家的动作恢复，绝不自动恢复。** 唯一手势是**关闭卡**（点「开始」/ 空格 / 点卡面）—— 因为要「看完手动关闭」。关闭后立刻回到 `ready`，奶龙在发射台待命，**不自动瞄准、不自动发射**。
3. **不再出现**：每张卡读完一次即写档（localStorage），**同卡永不重复**。重来本关、重开游戏都不再弹。理由：重来一次就得重读一次规则，是教学最招人恨的地方。
4. **打断即算没读**：卡打开期间若切后台／失焦，卡保持打开、**保持暂停**，回来仍在原卡。

**「第一次成功是保证的」怎么做到（【推】必须做到）**

- **第 1 发不允许失败**：第一段是「拖拽教学」，设计成**半引导** —— 死区线以下自由拖，拉过线即触发卡，卡上明说「松手就发射」，玩家第一次必定能把奶龙射出去（打到什么都不重要）。
- **第 2 发的连锁必须必然发生**：教学后面对的靶子只要碰到塔基就能倒一片。**当前第 1 关的 `(620,368/324/280)` 三连竖塔符合条件**（【算】塔基 15/37 个角度可命中）。

2. **每张卡 ≤ 45 字，且删掉也不影响操作。** 判定标准：把卡上的字全删掉，玩家还能不能玩下去？能 —— 那这张卡才是「解释」，不是「前提」。

5. **不做强制流程**：第 1 关不锁定「必须按顺序打」，玩家想先打右边那摞也可以 —— 卡只在他碰到对应目标时才出现。**教学应该「跟随」，而不是「押送」。**
6. **给跳过**：卡上放「我已知道」，跳过之后本卡永久不再出现。**跳过不是漏洞，是给二周目玩家的尊重。**

## 4. 四关木块摆放的玩法意见

### 4.1 先说三类「坏设计」的判据

**【推】** 以下三种摆法在弹弓物理解谜里最容易变成「一眼看不出怎么打」：

1. **挂点不存在 / 悬空**：块看起来搭着，实际靠物理引擎的休眠机制悬在半空。开局一有扰动就自己塌，玩家会以为是自己打崩的。
2. **唯一角度**：某个目标可命中的发射方向太少（个位数里只有 1–3 个），玩家只能靠试。**可玩空间太薄，运气成分盖过技巧。**
3. **看不见的承重关系**：视觉上「看着稳」，实际一碰就整片塌；或者「看着该塌」，实际纹丝不动。玩家的物理直觉被反复惩罚后就不敢出手了。

- **【推】护心块贴在岛左缘是全场最宽的直击窗口（12/37），这个安排是对的**：它让「第一发必须处理护心块」这件事变得明确。同时它也**拦在双塔前面**，所以「一杆扫完第一台」在几何上不成立 —— 这正是收束关该有的压力。
- **【推】修法**：把最高岛的 `(925,148)` 往左挪到 `(900,148)`（与落印块靠拢成一对），可打角度会上升；两块紧挨也更容易被一发同时处理。**约束：终局的两块可命中方向 ≥ 6/37。**
- **【算】三星率 39.0%（玩家基准）落在目标带内**，且**上一轮「第 4 关 ★★★ 判定偏松 98.5%」的问题已经不存在了** —— 那是旧几何的结论（旧版 65 条路线全部 3 发通关），重写后路线分布变成 3/7/10/14/29/25，二星三星分得开了。

### 4.5 岛屿与发数的微调额度（用户允许的部分）

- **岛屿**：**【推】建议不要动**。四关的岛面高度 `470 / 440–420 / 400 / 420–300–170` 已经构成一条清晰的「越爬越高」的线，这是本项目叙事的一部分；而且四关的岛都在 HUD 安全带（`y < 96`）之外，动岛容易引进新缺陷。
- **发数**：**【算】四关的 `birds`（6/6/6/7）都已经落在目标带内，建议全部维持**。理由见 §2.4：设计师的 8000 路线抽样给出 87.9% / 57.1% / 46.2% / 39.0% 的三星率，除了教学关刻意放宽，其余三关的形状是对的。
  - **唯一可能要动的是 `stars.two`，不是 `birds`**：把四关的 `two` 从 `1` 改成 `3`（见 §2.4）。
  - **改完任何摆放之后必须重测**：`node editor/run-search.mjs 1 2 3 4`（最少发数）+ `node editor/run-sample.mjs --n 8000`（发数分布）。**`M` 一变，`three = 2` 是否还成立就要重新确认**（要求 `B − three ≥ M`）。

## 5. 护心块与落印块：在新星级下还有价值吗

### 5.1 结论：有，而且比挂星级时更健康

**【码】** 两个机制的真实实现：

- **护心块**：`game.js:738` 一行 `if (kind === 'protect' && !b.hit) continue;` —— 没被奶龙直击过就完全不参与判定。**「护心」二字的全部实现就是这一行。**
- **落印块**：`game.js:745-749` —— `fell = Δy > 30`、`tilted = |angle| > 0.5`、`moved = |Δx| > 60`，且 `if (moved && !fell && !tilted) moved = false;`（平推不算）。

两者共同的性质：**免疫连锁，必须直击。**

**【推】为什么取消星级挂钩反而更好**：

- 挂星级时，玩家会为了「挣星」被迫去打一个自己不想打的目标。当那个目标的角度很窄（比如 §3.3 里 4/37 的落印块），玩家体验到的是**被设计逼迫**，而不是被挑战。
- 取消后，它们变成**清关的必经动作**（木块全倒才通关，免疫连锁的块只能靠奶龙亲自解决）。**「必须做」比「为了奖励而做」更干净**：不需要向玩家解释任何额外规则。
- 而且它们现在承担了**唯一的角度考验**：所有其他块都可以靠连锁解决，只有这两类块把「找角度」这件事锁死在玩法核心里。**在星级只数发数的系统里，它们就是「找角度」这个体验的承重墙。**

**【推】一个必须守住的前提**：既然它们成了清关必经动作，它们的**可打性就是关卡可通关性的前提**。§3.3 的 ≥8/37 阈值必须进验收脚本，否则会出现「关卡理论上无解」的灾难。

### 5.2 只说「剩几发」的星级，能否让玩家意识到要去打它们？

**不能靠星级本身。** 星级只反映发数，它不会告诉玩家「那边有块特殊的」。

**【推】靠三条链路补上（按优先级）：**

1. **「还差 1 块」的可见性 —— 最高优先。** 清关前最后几发，玩家的全部注意力都在「还剩什么」。**建议在 HUD 或底部提示条里做「剩余块种计数」**：`剩 2 块 · 护心 ×1`。理由：护心块免疫连锁，导致它天然会在最后剩下来，**「剩到最后的那块就是护心块」这个体验本身就会教会玩家护心块是什么** —— 不需要任何文字。
2. **世界内的即时反馈 —— 已有，确认保留。** 【码】护心块被连锁撞到时 `sClear('protect')` 的低闷木鱼音（`game.js:444-447`）、被连锁撞击时的静音（README 说明），加上落印块倒下时的 `seal()` 落印音（`game.js:440-443`），三者构成完整的「打错了 / 打对了」听觉语言。**这是本项目最好的一处设计，不要为了省事合并音效。**
3. **每发之后的提示条**（`chip`，3.6 秒）——【推】建议在提示条里加**一次性**的「规则复习」：当玩家第一次直击护心块、或第一次把落印块推出去 60px 却不算倒时，提示条弹一句：
   - 护心：`护心块只认奶龙直击 —— 连锁撞它没用`
   - 落印：`推着走不算落印，得压平或掀翻`
   **只弹一次，之后永不重复。** 规则复习只在「玩家刚犯错」时出现，最省注意力。

### 5.3 一个副产品：护心块现在是最好的教学载体

**【推】** 由于护心块免疫连锁，它天然是「必须先规划角度」的教具。第 2 关把它放在首屏最显眼处（10 个可打角度），玩家第一发就能直击它 —— **「啊，原来这块得我自己打」这个认知，用一次成功就能建立**。这比任何文字都快。建议第 2 关的护心块位置**不要动**。

## 6. 难度曲线与「每关都要找角度」的冲突检查

### 6.1 冲突是真的存在，但可以定位到具体环节

**【推】** 只看发数的星级，会不会把「找角度」退化成「必须找到唯一解」？答案取决于阈值落在哪：

| 情况 | 结果 | 玩家体验 |
|---|---|---|
| `T3 = B − M`（最少发数） | 三星 = **必须走最优路线** | 如果最优路线只有一条窄角，就是「必须找到唯一解」 |
| `T3 = B − M − 1` 及以上 | 三星 = 允许一发容错 | 不可能（见 §2.1：会变成白送） |

**所以是的，风险成立。** 但危险的**不是**「必须走最优路线」这件事本身，而是**「最优路线只有一条窄角度」**。这两件事必须分开处理：

> **正确的应对是提高「最优路线的角度宽度」，而不是放宽三星阈值。**

判据（**【推】建议写进验收**）：`M` 发通关的路线中，**至少要有 8 个不同的发射方向**能成。这正是 §3.3 的阈值该管的事。

### 6.2 松容错 + 紧三星：两者其实在互相帮衬

**【推】** 这里有一个反直觉但重要的结论：

- **容错 `B − M` 越大** → 三星越难（`T3 = B − M` 越小）→ 但玩家有更多次失败机会去试角度
- **容错越紧** → 三星越容易（阈值更宽）→ 但玩家不敢试错

所以 **「容错松 + 三星紧 = 探索友好、精通困难」**，这恰好是我们想要的手感：**允许你多打几发去摸索，但拿三星必须摸到极限。** 建议保留 2–3 发的容错，不要为了制造紧张感去压缩它。**发出「紧张感」的任务交给结算面板的差值（差 1 发），而不是交给额度。**

### 6.3 必须给玩家的第三档反馈：这一把已经拿不到三星了

**【推，重要】** 如果玩家第 3 发打空，而三星要求 2 发内，那么这一把剩下的过程就完全失去意义 —— 但游戏什么都不说，玩家会继续打 3 发才发现。**这是体验上最伤的一处。**

建议：**在「已经不可能三星」的那一发结束后的提示条里明说**：

```
这一把三星没了（三星要 2 发内）· 打完还能重来
```

这句提示同时做三件事：① 停止无意义的期待；② 预告重来（§2.6 第 3 条）；③ 把「重来」从失败变成选择。**不要用弹窗、不要淡出游戏，只用提示条。**

### 6.4 难度曲线的整体形状

**【推】** 按「找角度的难度」而不是「木块数量」来看四关：

```
第 1 关  教「拆底部」（连锁）                     —— 角度很宽（可命中方向 13~15/37）
第 2 关  教「必须亲自打的块」（护心块免疫连锁）    —— 角度收窄到 10/37
第 3 关  教「多段结构」（四层柱、楔块、双柱）      —— 角度 8~15/37，但结构复杂
第 4 关  教「一发两段」（骑缝摞 + 三连落印）       —— 角度 4~15/37，最窄
```

这个曲线是**健康的**：宽度在收窄、结构在变复杂，两条线同步上升。**唯一的问题是第 4 关的窄角度块（4/37）和第 1 关的承重块（2/37）落在曲线的两端，制造了「第一关比第四关还难打中」的错位感。** 修掉这两处，曲线就完整了。

## 7. 图纸信息层级规范（960×540 平面图）

### 7.1 一套规则解决「图纸不互相打架」

**【推】核心手法：每个图层只允许占 1 个视觉重量，而且重量必须与语义匹配。**

| 层 | 内容 | 视觉重量 | 说明 |
|---|---|---|---|
| L0 | 纸底 | 无 | `#faf5e8` 平涂，无渐变无滤镜 |
| L1 | 44px 栅格 | 最弱 | `#efe6d2`（关键线 `#e2d6b8`）—— 量对齐用，不能抢眼 |
| L2 | 岛体 | 弱 | 淡青绿填充 + 青绿描边，岛面线加粗 |
| L3 | HUD 安全带 | 弱 | 8% 墨灰填充 + 虚线，**压在最上层**（否则会被木块压住看不见） |
| L4 | 木块 | 中 | 赭木双框 + 墨色描边（普通）／墨圈（护心）／朱砂实心（落印） |
| L5 | 参考弹道 | 强 | 朱砂虚线为主、墨灰点线为备选 |
| L6 | 批注 / 尺寸 | 中 | 墨色文字 + 极细引线 |

**关键取舍：关掉 HUD 之外的 UI 图层，关掉装饰。** 图纸只画「这一关是谁、在哪、怎么打」，不画苔点、垂藤、远山 —— 那些属于游戏画面，不属于平面图。

### 7.2 配色（严格遵守既有视觉系统）

```
纸    #faf5e8   画布底
墨    #2b2b2b   文字、木块描边、批注
淡墨  #5a5750 / #9a958a   次要文字、网格、备选弹道
朱砂  #b23a2e   一切「动作」：参考弹道、力度箭头、落印块、缺陷批注
深朱  #7f2a21   落印块描边、警示文字
青绿  #4e7a5e / #e7efe6   岛体（画布内）
赭木  #b98247 / #fbeee0   木块（画布内）
```

三条硬规矩（都来自用户给的视觉系统）：

1. **纸是底、墨是字、朱砂是动作** —— 所以**图例、坐标标注、尺寸数字一律墨色**，只有弹道、力度、缺陷用朱砂。**朱砂一旦用来写字，就不再表示「动作」了。**
2. **青绿与赭木只在画布内**（`0 ≤ x ≤ 960, 0 ≤ y ≤ 540`）。落到画布外的说明区一律用墨+纸。
3. **不引入这套调色板之外的任何颜色**：不用蓝、不用紫、不用纯黑 `#000`、不用纯白 `#fff`。

### 7.3 信息层级的三条设计决定（附理由）

1. **岛体不填满色，木块不填重色。** 理由：一张图里，玩家最需要一眼找到的是**木块和弹道**。岛如果填满青绿、木块再填重赭，整张图会变成一张色块拼贴，眼动成本立刻上去。所以岛用「淡填充 + 实描边」占住位置，木块用「浅填充 + 双描边」保证 44px 尺度下形状可辨。
2. **弹道线压在木块之上。** 理由：弹道与木块**交叠**本身就是信息（「这一发会先撞到哪一块」），虚线穿过木块反而帮助阅读；如果把弹道压到木块下面，交叠点会被遮住。
3. **弹道不超过 3 条，且用线型区分主次，不用颜色区分。** 理由：**颜色只有一个语义维度（朱砂=动作）**，用深浅区分主备会让玩家以为「浅的那条是别的东西」。所以主弹道 = 朱砂粗虚线，备选 = 墨灰点线。

### 7.4 每张图的固定版式（已按此生成，见 §9）

```
标题条   y 0–34      关名 + 木块数/奶龙数（纸色底压住网格，保证可读）
画布     0–960 × 0–540   960×540 世界 1:1，不缩放、不加边距
左下达注 y ≈ 400 起   「这一关怎么打」：3 条顺序解说 + 一句本关定位
右下图例 y ≈ 430 起   6 条图例，纸色卡 + 墨框
HUD 带   y 0–96      顶部虚线标注「木块不得进入」
```

**【推】为什么不做「图外说明栏」**：会破坏 1:1 世界坐标，让「这块木块离 HUD 带几像素」这类判断失真。**保持 1:1，是所有标注能直接读成游戏数值的前提。**

### 7.5 可访问性与离线约束

- **不靠颜色单独区分**：护心 = 木色 + 墨圈 + 字形「护」；落印 = 朱砂块 + 纸色「印」；普通 = 墨框双线。**三种块在灰度打印下依然可辨。**
- **不用 emoji 当图例**：SVG 在离线环境下的 emoji 字形依赖系统字体，可能变成方框。一律用手绘图形（圆形、方块、虚线）与汉字。
- **字体栈必须收敛**：`"Noto Serif SC","Source Han Serif SC","Songti SC","SimSun",serif`，坐标数字用 `Consolas/等宽`。**不引用任何外部字体、不引用任何 CDN、不引用任何位图。**
- **不设 `font-size` 全局继承依赖**：每段文字显式写尺寸（12 / 11.5 / 11），避免不同浏览器默认字号差异导致跑版。
- **不写 `opacity` 混色**：图纸用实色，避免「看似同色、实际不同」的读数困难（这一条与游戏 canvas 的 0.12 alpha 用法不同，属图纸专属规范）。
